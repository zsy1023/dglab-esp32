# dglab-esp32

**在 ESP32 上复刻 DG-LAB 郊狼主机（Coyote）3.0 的 BLE 外设 —— 而且板子自己就是一台主机。**

让手机里的官方 DG-LAB App 以为自己在连一台真郊狼主机：`B0`/`BF` 指令由**本固件**解析，
A/B 通道强度、软上限、波形都由本固件维护，需要回 `B1` 时自己回 —— **手机单独连板子就能调强度**，
不依赖 PC 在线。同时把这些原始指令照旧经一根 USB 串口转交给 PC 侧上位机（PC 从此只是「观察者」）。

```
控制者手机 DG-LAB App ──BLE──▶ ESP32（本固件 = 主机，自己回 B1）
                                    │
                                    └──串口 115200──▶ PC 侧上位机（只收原始帧 + '#' 日志，不再回 B1）
```

> English version: **[README.en.md](README.en.md)**

## 它做什么 / 不做什么

**做**（"忠实还原一台主机"）：

- 复刻真机 GATT 全表 + 广播名 `47L121000`（含官方文档里没写的特征）
- 复刻真机行为：订阅 `0x150B` 成功后**立刻**发 6 字节 `53 00 <MAC 后 4 字节>`
- **★ 主机逻辑**：`B0` → A/B 通道强度（绝对 / 相对 / 受软上限夹值）、两通道 4 组波形；
  `BF` → 强度软上限 + 平衡参数（软上限**断电保存**）；序列号 ≠ 0 时回 `B1`
- `B0`/`BF` 原样经串口上行（上位机想看就看，不想看可以发一个 `0xC0` 关掉）
- 串口日志（**纯 ASCII**）直接把强度 / 波形 / 软上限打出来，串口监视器就能看
- 断开后自动重新广播

**不做**（留给 PC 侧上位机）：

- 波形叠加、惩罚逻辑、规则判定
- 联网 / 中继 / 多设备编排

> 换句话说：本固件=**一台真主机 + 一根透明的旁路管道**。

## 2. 端口与接口（上游链路）

### 2.1 与上位机的串口 —— 这就是"上游"

| 项 | 值 |
|---|---|
| 物理接口 | 板载 USB 转串口（WCH CH340） |
| **串口参数** | **115200 8N1，无硬件流控** |
| **识别方式** | `USB VID:PID = 1A86:7523` |
| 端口号 | 本机实测 `COM18`（换机器 / 换 USB 口都会变） |
| 用途 | 供电 + 烧写 + **与上位机的数据链路**（同一条口） |

> ⚠️ **别选到 Windows 蓝牙虚拟串口**（常见 `COM5`/`COM6`）。它**能打开成功，却一个字节都收不到**，
> 表现为"看着正常但没数据"。认准 `VID:PID = 1A86:7523` 的那一个。
>
> ⚠️ 串口是**独占**的：烧写 / 监视之前必须先停掉上位机进程，否则打不开，或者两边抢字节。

### 2.2 上行：ESP32 → 上位机

| 帧 | 长度 | 含义 |
|---|---|---|
| `0xB0` + 19B | **20** | App 的 `B0` 指令，**原样透传**（默认不发，见下） |
| `0xBF` + 6B | **7** | App 的 `BF` 指令，**原样透传**（默认不发，见下） |
| `0xCC` | **1** | App 已连上 |
| `0xCD` | **1** | App 已断开 |
| `#` 开头的文本行 | 变长 | 人类可读日志（上位机按行丢弃，见 [§4.2](#42-日志约定二进制帧和文本日志怎么共存)） |

> **原始帧默认不发**：只有收到上位机的 `0xCE` 心跳之后才开始发（上位机启动时的在线探测就会发一次，
> 所以 **PC 侧代码不用改**）。这样"手机单独连板子"时，串口监视器里不会有二进制乱码。
> 想手动切换：发 `0xC1` 打开、`0xC0` 关闭（`#STAT` 里的 `raw=` 就是当前状态）。

### 2.3 下行：上位机 → ESP32

| 帧 | 长度 | 含义 |
|---|---|---|
| `0xCE` | **1** | 心跳 → 固件回一条 `#` 日志行（在线探测），并**顺便打开原始帧上行** |
| `0xC0` / `0xC1` | **1** | **关 / 开**「原始帧上行」。关掉（`0xC0`）后上位机就收不到 `B0`/`BF` 了 —— 只在调试时用 |
| `0xC2` / `0xC3` | **1** | **关 / 开**「逐条 `B0` 详单」（**默认开**）。开着每条 `B0` 打一行（每 100ms，就是 App 的写入节奏）；嫌吵就发 `0xC2` |
| `0xD0` + 2B | **3** | **强度绝对值** `0xD0 ch value`：value 0~200（超过按 200），受软上限夹值 |
| `0xD1` + 2B | **3** | **强度相对增减** `0xD1 ch delta`：delta 是 int8（`0xFF` = −1，`0x01` = +1） |
| `0xD2` + 2B | **3** | **回路开关** `0xD2 ch on`：`0` = 断开（真机上没有电流）/ 非 0 = 闭合 |
| `0xB1` + 3B | **4** | **已废弃、会被忽略**（只记一次警告）。主机逻辑搬进固件后，强度回包以固件为准，上位机别再发 |

> 这几个控制字节就是为了"在串口监视器里手动切"设计的：在监视器的发送框里发一个 `C0`/`C1`/`C2`/`C3` 即可。
>
> `0xD0/0xD1/0xD2` 的通道字节 `ch`：**`0` = A 通道，`1` = B 通道，`0xFF` = 两个都改**。
> 强度改完固件会回一条 **`B1(seq=0)`**（真机拨轮改强度也是这么回的），手机 App 的显示会跟着同步。

### 2.4 蓝牙侧：手机 App → ESP32

| 项 | 值 |
|---|---|
| 广播名 / 设备名 | `47L121000` |
| 广播内容 | **只有名字**，不带服务 UUID、不带厂商数据 |
| 连接间隔 | 连接后固件请求 15~30ms（最终由作为 central 的 App 决定） |
| MTU | 23（真机实测值；20 字节的 `B0` 正好放得下） |
| 服务 / 特征 | 见 [§5 复刻的 GATT 表](#5-复刻的-gatt-表) |

### 3.1 串口示波台（网页版，推荐）

`tools/serial_scope.html` —— **单文件网页**，用浏览器的 Web Serial 直接连板子的 COM 口，
把固件打的 `#` 日志变成"活"的界面，也能反过来控制（不用装任何东西、不用起后端）：

- **看**：A/B 通道强度（当前 / 软上限）、每 25ms 一组的**波形面积图 + 频率曲线**（滚动 10 秒）、
  回路通断、B0 帧率、手机 App 连没连 / 订阅没订阅、最后一次 `B1` 回包
- **波形区还会直说"现在到底有没有输出"**：`输出中（峰值/频率）` / `波形强度全 0` /
  `整组作废（哪组越界）` / `回路断开` / `还没收到 B0` —— 不用再猜为什么看不见波形
- **控**：A/B 各自的**回路开关**（`0xD2`）、强度 **−/＋ 点动**（按住连发，`0xD1`）、
  强度**绝对值设置**（`0xD0`）。改完固件会回一条 `B1(seq=0)`，手机上 App 的显示也会跟着走

用法：

1. **先关掉串口监视器 / PC 侧上位机**（串口是独占的）
2. Chrome 或 Edge 打开 `tools/serial_scope.html`
   （`file://` 一般就能用；不行就在该目录 `python -m http.server 8000`，再开 `http://localhost:8000/serial_scope.html`）
3. 点「连接串口」→ 选板子的口（115200 8N1）。板子可能在打开时**复位一次**（DTR/RTS 抖动），正常

> 网页**从不发 `0xCE`**（那会让固件把原始二进制帧也上行出来）。它只发 `0xC3`（逐帧日志）和
> `0xD0/0xD1/0xD2`（强度 / 回路）。解析逻辑有脱浏览器单测：`tools/serial_scope.html` 里的
> `handleLine` 能直接喂固件日志行验证。

### 3.2 上位机 Python 示例（实时拿强度）

`examples/host_example.py` —— 自己写上位机时直接抄这个，只依赖 `pyserial`：

```bash
pip install -r examples/requirements.txt

python examples/host_example.py --list                  # 列串口（会标出最像 ESP32 的）
python examples/host_example.py --port COM19            # 实时打印强度/波形/回路（Ctrl+C 停）
python examples/host_example.py --port COM19 --set A=20 --loop B=off --for 5   # 控制 + 看 5 秒
python examples/host_example.py --selftest              # 不接板子，自测解析逻辑
```

实时性来自**固件每 100ms 一条的 `#B0` 日志**（每帧 4 组 × 25ms 的波形都在里面），
示例把它解析成：

```
A  20/150 [闭环] wA=20:40,20:50,20:60,20:70 峰 70 | B   0/30  [断开] wB=!0:0,0:0,0:0,0:101 | app=连上/已订阅 b0=10.0/s
```

当库用：

```python
from examples.host_example import DglabLink, CH_A, CH_B

link = DglabLink("COM19", on_event=lambda ev: print("[事件]", ev))   # 强度变化 / 回路 / B1 都会回调
link.open()                       # 自动发 0xC3（开逐帧日志）+ 0xC0（不要原始二进制帧）

print(link.state.a.strength)      # A 通道当前强度（每 100ms 刷新一次）
print(link.state.a.cap)           # A 通道软上限
print(link.state.a.wave)          # [(频率, 强度) × 4]
print(link.state.a.outputting)    # 现在到底有没有在输出（回路 + 波形合法性 + 峰值）
print(link.state.b0_rate)         # 实际帧率（正常 10.0，掉帧一眼看出）

link.set_strength(CH_A, 20)       # 0xD0：绝对值（受软上限夹值）
link.step_strength(CH_B, +1)      # 0xD1：相对增减
link.set_loop(CH_B, False)        # 0xD2：回路断开
link.close()
```

改强度的效果**手机 App 也看得见**：固件会回一条 `B1(seq=0)`，App 用它刷新显示。

自测（假串口，不需要板子，验证解析 + 三个控制帧 + 打开时发的字节）：

```bash
python examples/test_host_example.py
```

## 4. 串口帧协议（契约）

固件侧常量见 `src/main.cpp` 顶部；上位机侧照此实现即可。**改这里必须两边同时改。**

### 4.1 分帧方式

靠 **HEAD 字节定长分帧**：没有长度前缀、也没有校验和。

- 长度 / 帧头不符合契约的写入**不进链路**（避免污染定长分帧），但会打日志记录下来。
- 固定波特率 **115200 8N1**（两边必须一致）。

### 4.2 日志约定：二进制帧和文本日志怎么共存

固件所有人类可读日志都是 **`#` 开头 + `\n` 结尾**，上位机在分帧时**整行丢弃**：

```
#dglab-esp32 boot: name=47L121000 bt_mac=EC:E3:34:A9:13:0E
#caps: host_logic=1 (firmware owns strength+B1) soft_cap=150/30 raw_uplink=0 verbose_b0=1
#App connected (conn_id=0) | strength A=0/150 B=0/30
#0x150B subscribed -> device handshake 53 00 34 A9 13 0E
#B0 t=1520 seq=0 mode=A./B. set=0/0 A=0/150 B=0/30 link=A1/B1 wA=10:0,10:10,20:20,30:30 wB=!0:0,0:0,0:0,0:101 raw=B00000000A0A0A0A000A141E0000000000000065
#B1 -> App seq=1 A=5 B=0
#STRENGTH A=5/150 B=0/30 (seq=1)
#STAT t=2620 A=5/150 B=0/30 link=A1/B1 wA=10:0,10:10,20:20,30:30 wB=!0:0,0:0,0:0,0:101 | b0=12 (10.0/s) bf=1 b1=1 drop=0 down=0 logdrop=0 conn=1 sub=1 raw=0 verbose=1
```

一眼就能看出**强度**（`A=5/150` = 当前值/软上限）、**波形**（`wA=` 4 组 `频率:强度`，
逗号分隔**保持成一个 token**，网页/上位机好解析）、**回路**（`link=A1/B1`，1 = 闭合 / 0 = 断开）、
**软上限**（`BF` 那条 `SOFT LIMIT`）。日志**一律纯 ASCII**：

> **`!` 前缀 = 该通道 4 组整组作废**（真机不输出）。作废时**数字照样打出来**
> （`wB=!0:0,0:0,0:0,0:101` → 频率 0、强度 101），这样"为什么没波形"一眼看得出来；
> 行尾 `raw=` 是这条 `B0` 的**原始 20 字节**，是排障的最终证据。
>
> ⚠️ 别在日志里打中文。早期版本打的是 UTF-8 中文，在按 GBK 解码的串口监视器里会变成
> 「宸茶繛鎺ワ（conn_id=0锛」这种乱码。ASCII 在任何编码下都不会乱。

**刷新率**：`#B0` 默认每条都打，跟着 App 的写入节奏走 —— **100ms 一帧，每通道 4 组、每组 25ms**，
这就是 V3 协议能给到的最快粒度（再快协议里没有）。行首的 `t=` 是 `millis()`，
可以直接核对节奏有没有抖（正常应该 100ms 一跳）。`#STAT` 还带 `b0=12 (10.0/s)`，一眼看出有没有掉帧。

日志行一览：

| 行 | 什么时候打 |
|---|---|
| `#B0 t=.. link=.. wA=.. wB=.. raw=..` | **每条 `B0` 都打**（每 100ms）—— 强度、解读方式、设定值、回路、两通道 4 组波形、原始 20 字节 |
| `#STRENGTH A=/B=` | 强度变了才打（App 调的 / 串口 `0xD0`/`0xD1` 调的 / 软上限收紧） |
| `#SOFT LIMIT ...` | 收到 `BF` 时打（软上限 / 平衡参数） |
| `#link: loop A=closed B=open ...` | 回路开关变了 |
| `#B1 -> App seq=..` | 回了一条强度回包（手机上调强度成功的关键证据） |
| `#STAT t=.. ... b0=(n/s)` | 周期心跳：连上时 1 秒一条，没连时 5 秒一条；带 B0 条/秒，能看出有没有掉帧 |
| `#IGNORED (not a host B0/BF opcode) len=.. ..` | App 写了非主机指令（灵猫/爪印那种 `50`/`BC`/`C3`/`C4`/`FF`），照契约忽略并记账 |

嫌 `#B0` 刷屏就发 `0xC2` 关掉（`0xC3` 再打开）；TX 挤不下时日志会**丢行而不是阻塞**，
丢了会计进 `#STAT` 的 `logdrop=`。

`#`（`0x23`）**不在帧头集合里**，所以两者不会互相误判；帧体内部的 `0x0A` 也不会被当成换行
（只在"等帧头"时才按行丢弃）。这条约定让**日志**和**协议**共用同一个 UART0 而互不干扰。

> ⚠️ 用本固件时**别往同一条串口打不带 `#` 的文本**。
>
> ⚠️ 原始 `B0`/`BF` 帧是**二进制**，在文本监视器里本来就是"乱码"（`\0`、换行、怪字符）。
> 它们默认**不发**（要等上位机的 `0xCE` 心跳）；想手动打开/关闭就发 `0xC1` / `0xC0`。

### 4.3 故障与保护

固件侧已实现：

- **半帧看门狗**：收到帧头后 200ms 还没凑齐 → 丢弃重同步（否则丢一个字节会把下行永久卡死）。
- **订阅边沿检测**：轮询 `BLE2902`（CCCD）本地值，上升沿发设备握手（Bluedroid 会在 central 写 CCCD 时更新它）。
- **在线应答**：收到 `0xCE` 回一条 `#` 日志行。

上位机侧建议实现：

- **上行缓冲兜底**：缓冲超过 4096 字节 → 清空重同步。
- **在线探测**：打开串口后发 `0xCE`，收不到任何帧 / 日志行就**明确报错**
  （"打开成功但对面没应答" = 填错口 / 没烧固件），不要静默假死。
- **断线重连**：拔线 / 复位 / 端口被抢占都要能自动退避重连。

### 4.4 主机逻辑（本固件自己算强度）

状态机在 `src/host_state.h`（**纯 C++，一行 Arduino/BLE 代码都没有**，可以拿 `g++` 直接单测）。
语义严格照官方 V3 规格 + 真机实测：

| 规则 | 实现 |
|---|---|
| `B0` 的强度解读方式（byte1 低 4bit） | `00` 不变 / `01` 相对加 / `10` 相对减 / `11` 绝对设置 |
| 强度设定值越界（>200） | **按 0 处理**（不是夹到 200 —— 官方文档 e.g. 4 明确写了） |
| 强度绝对值 | 夹在 `0 ~ 软上限`，软上限来自 `BF`（**断电保存**，存 NVS） |
| 波形合法性 | 频率 `10~240`、强度 `0~100`，**任一越界 → 该通道 4 组整组作废** |
| 回 `B1` 的时机 | **序列号 ≠ 0 就回**（真机实测：哪怕强度一个字节都没变也回） |
| `BF` 软上限 >200 | 不修改（官方文档：输入范围外不修改） |
| 串口 `0xD0/0xD1` 改强度 | 与 `B0` 走**同一套** `step()`：受软上限夹值，改完回 `B1(seq=0)`（等于真机拨轮） |
| 串口 `0xD2` 回路开关 | A/B 各自独立；断开只影响"有没有输出"，强度保留（真机断电极就是这样） |

> 为什么 B1 必须回：App 调强度后会**锁住输入**，直到收到同序列号的 `B1`。
> 收不到 = 手机上怎么点强度都不动、面板一直显示 0。这就是"PC 没连时强度是零"的根因。

**上位机侧要跟着改的（重要）**：

1. **别再往串口写 `B1`** —— 固件已经是主机，自己回；收到上位机的 `B1` 会忽略并记警告。
2. 想显示强度：继续解析上行 `B0` 自己算（和固件同一套规则），或者直接读 `#STRENGTH` / `#STAT` 日志行。
3. `0xCE` 心跳、`B0`/`BF`/`CC`/`CD` 上行都没变，老代码不用动也能跑（心跳会自动打开原始帧上行；
   别再写 `B1` 就行）。
4. 串口是**独占**的：开着串口监视器时上位机打不开同一个口，反之亦然。

## 5. 复刻的 GATT 表

| 服务 | 特征 | 属性 | 值 / 说明 |
|---|---|---|---|
| `0x1800`（协议栈内建） | `0x2A00` 设备名 | read, write | `47L121000` |
| | `0x2A01` / `0x2AA6` | read | Appearance / 地址解析 |
| `0x1801`（协议栈内建） | `0x2A05` | indicate | Service Changed |
| `0x180C` | `0x150A` | **write-without-response** | App 的所有指令（**不是普通 WRITE！**） |
| | `0x150B` | notify | 本固件的所有回包（`B1`、握手等） |
| `0x180A` | `0x1500` | read, notify | 电量，1 字节百分比（`0x64` = 100%） |
| | `0x1501` | read | `0c 03` —— **App 靠它判定协议 V3，必须照回** |
| | `0x1502` | read | 6 字节本机 MAC |
| | `0x2A25` | read | `"CEB3%Q"` + MAC（12 字节） |
| | `0x2A59` | read, notify | 10 字节输出状态回读（见 [§7](#7-已知问题--待办) 第 1 条） |
| `0x2003` | `0x0007` / `0x0008` | write / read+notify | 用途未知，照真机提供 |
| `0x2004` | `0x0009` | read, write | 同上 |
| `0xFE59` | Nordic DFU | — | **不复刻**（真机有，App 不需要） |

行为细节（都是真机实测，不是照官方文档）：

- 广播里**只有名字**，不带服务 UUID、不带厂商数据；
- 订阅 `0x150B` 成功后**立刻**发 6 字节 `53 00 <MAC 后 4 字节>`；
- 断开后**自动重新广播**（否则手机再也搜不到）。

App 初始化流程（照此顺序复刻）：

```
read(180A/1500) → read(180A/1501) → notify(180A/1500)
   → notify(180C/150B) → check(180C/150A) → notify(180A/2A59)
```

## 6. 延迟

一次"App 调强度 → 界面回显"要经过：
`BLE 往返` + `串口上行` + `上位机解析/回包` + `串口下行` + `BLE 通知`。

本机实测：

| 段 | 耗时 |
|---|---|
| 串口回路（上位机写 → 固件处理 → 上位机收到），**优化后** | **p50 4.5 ms** |
| 同上，优化前（上位机侧一次 `read(256)` 阻塞） | p50 87.9 ms ← 曾经的"反应慢"元凶 |

固件侧为此做的：`loop()` 轮询 1ms、连接后请求 15~30ms 的快速连接参数、
状态行 `#STAT` 连上时 1 秒一条（没连时 5 秒一条，少占串口）。

一次"App 调强度 → 界面回显"现在**不经过 PC**（固件自己回 `B1`），只剩
`BLE 写入` + `固件算 + 排 B1` + `loop` 里 `notify`，实测亚毫秒级排队（`loop` 1ms 一轮）。

### 6.1 脱硬件单测（改状态机必跑）

`src/host_state.h` 没有 Arduino 依赖，拿任意 g++ 编译就能测：

```bash
# 在 firmware/ 目录下
g++ -std=c++11 -Wall -Wextra -I src -o test_host_state tools/test_host_state.cpp && ./test_host_state
```

覆盖：相对/绝对强度、越界设定值按 0、软上限夹值、收紧软上限立刻压回、
`seq≠0` 必回 `B1`、波形越界整组作废、长度/HEAD 不符不改状态、
以及官方 `example.md` 里的真实报文。

## 7. 已知问题 / 待办

1. **`0x2A59` 是近似复刻**：真机的精确编码规则仍未解出（只知道它随 `B0` 的波形变）。
   当前实现是字节 0-1 恒 `01 01`、字节 2/3 跟 A/B 通道的波形强度走、其余保持基线。
   App 订阅了它，目前工作正常；要精确复刻需要拿真机多测几组。
2. **`0x1800` 下缺 `0x2A04`（首选连接参数）**：该特征由 ESP-IDF 协议栈按编译配置提供，
   当前 Arduino core 的预编译库没开，补它要重编 IDF。
   所以改用"连接后主动请求快速连接参数"达到同样目的。
3. **App 还会往 `0x150A` 写非主机指令**（实测一连上就来几条，形如
   `50 02 00 00 …`(灵猫)、`BC 04 32 32 32 1E 50 96 32`、`C3 06 …`、`C4 0A`、`FF`）。
   这些是**灵猫 / 爪印那类设备的命令头**，主机上语义未知：按契约忽略并打
   `#IGNORED ...`（不污染上行帧流）。目前实测不影响功能。
4. **未加密链路上 `0x1500`/`0x2A59` 的订阅**：真机在 Windows 侧也会被拒（`Access Denied`），
   是链路 / 主机侧的限制，手机 App 那边不受影响。
5. **`B1` 只在序列号 ≠ 0 时回**（照真机实测）。真机还有"拨轮改强度 → 回 `seq=0` 的 `B1`"，
   本固件没有物理拨轮，所以不会出现。App 用绝对/相对指令改强度是能看到的。
